# Инструкция по запуску и тестированию `policl7`

Это руководство рассчитано на Windows и PowerShell. Выполняйте действия по порядку. При запуске оставляйте каждый сервис в отдельном окне PowerShell: пока в окне идут журналы приложения, оно занято этим сервисом. Секреты подключения нигде не публикуйте.

## 1. Что входит в проект

В проекте есть старое веб-приложение (монолит) с Thymeleaf-страницами и три отдельных бизнес-микросервиса. Монолит оставлен для веб-страниц; Gateway направляет HTML-маршруты к нему, а API — к соответствующим микросервисам.

| Приложение | Назначение | Порт |
|---|---|---:|
| Config Server | Отдаёт общие и сервисные настройки из `microservices/config-repo` | 8888 |
| Eureka Server | Реестр, где сервисы находят друг друга | 8761 |
| Identity Service | Регистрация, профиль и административные операции с пользователями | 8081 |
| Appointment Service | Записи на приём и каталог услуг | 8082 |
| Medical Record Service | Медицинские записи и назначения | 8083 |
| Монолит с профилем `cloud` | Thymeleaf-интерфейс и совместимость веб-сценариев | 8084 |
| API Gateway | Единая точка входа в API и веб-интерфейс | 8080 |

Используются Java 17, Spring Boot 3.2.0, Spring Cloud 2023.0.0 и Springdoc 2.3.0. В проекте есть Maven Wrapper (`mvnw.cmd`), поэтому отдельная установка Maven обычно не нужна.

Бизнес-сервисы используют существующую PostgreSQL и ожидают настройки через переменные `MEDICAL_DB_URL`, `MEDICAL_DB_USERNAME`, `MEDICAL_DB_PASSWORD`. Значения по умолчанию в конфигурации указывают на `localhost:5433/policl`. Пароль и логин здесь намеренно не приводятся. Для монолита используйте исключительно профиль `cloud`: в нём включена проверка существующей схемы (`validate`), отключено создание таблиц сессий и демонстрационное заполнение. Не запускайте монолит без этого профиля для этой инструкции.

## 2. Подготовьте компьютер

### 2.1 Откройте PowerShell в папке проекта

1. Откройте Проводник и перейдите в папку проекта, например `D:\Music\policl7`.
2. Нажмите правой кнопкой мыши по свободному месту папки и выберите «Открыть в Терминале» (или откройте PowerShell и выполните команду):

```powershell
Set-Location -LiteralPath 'D:\Music\policl7'
```

Если проект находится в другом месте, подставьте свой путь. Убедитесь, что текущая папка верная:

```powershell
Get-Location
Test-Path .\mvnw.cmd
```

Первая команда должна показать корневую папку проекта, вторая — `True`.

### 2.2 Проверьте Java и Maven Wrapper

```powershell
java -version
```

Ожидается версия Java 17. Если команда не найдена или версия другая, установите JDK 17 и откройте новое окно PowerShell.

```powershell
Test-Path .\mvnw.cmd
.\mvnw.cmd -version
```

Ожидается `True` и сведения о Maven/Java. Wrapper — это скрипт проекта, который запускает нужный Maven без отдельной глобальной установки.

### 2.3 Проверьте PostgreSQL и порт

Служба PostgreSQL должна быть запущена. Посмотрите найденные службы, не меняя их:

```powershell
Get-Service '*postgres*' | Select-Object Status, Name, DisplayName
```

Если служба есть, ожидаемый статус — `Running`. Проверить доступность настроенного проектом порта можно так:

```powershell
Test-NetConnection localhost -Port 5433
```

Ожидается `TcpTestSucceeded : True`. Если порт недоступен, не создавайте новую базу и не меняйте схему: проверьте, запущена ли именно существующая база и совпадает ли её адрес с настройкой проекта. Клиент `psql` для запуска приложений необязателен.

## 3. Загрузка настроек базы для микросервисов

Каждому окну PowerShell нужна собственная копия переменных окружения. Перед запуском **каждого** бизнес-сервиса вставьте в его окно весь следующий блок. Он читает только три параметра подключения из уже существующего `src\main\resources\application.properties`, присваивает их переменным текущего окна и не печатает значения:

```powershell
$propsFile = Join-Path (Get-Location) 'src\main\resources\application.properties'
if (-not (Test-Path -LiteralPath $propsFile)) { throw 'Не найден src\main\resources\application.properties. Сначала перейдите в корень проекта.' }
$dbProps = @{}
foreach ($line in Get-Content -LiteralPath $propsFile) {
  if ($line -match '^\s*spring\.datasource\.(url|username|password)\s*[=:]\s*(.*?)\s*$') {
    $dbProps[$Matches[1]] = $Matches[2]
  }
}
if (-not $dbProps.ContainsKey('username') -or -not $dbProps.ContainsKey('password')) { throw 'В application.properties не найдены необходимые параметры БД.' }
$env:MEDICAL_DB_URL = if ($dbProps.ContainsKey('url')) { $dbProps['url'] } else { 'jdbc:postgresql://localhost:5433/policl' }
$env:MEDICAL_DB_USERNAME = $dbProps['username']
$env:MEDICAL_DB_PASSWORD = $dbProps['password']
Remove-Variable dbProps, line, propsFile
'Настройки подключения загружены в это окно (значения скрыты).'
```

Не вводите `Get-ChildItem Env:` и не печатайте переменные `MEDICAL_DB_*`: так можно случайно показать пароль. Переменные исчезают при закрытии окна PowerShell. Если параметры в вашем файле заданы через ссылки на другие переменные, блок не сможет разрешить ссылки — остановитесь и уточните конфигурацию, не подставляя пароль в чат.

## 4. Соберите и проверьте тесты

Перед запуском тестов микросервисов загрузите переменные подключения к PostgreSQL **в том же окне PowerShell**, из которого будете запускать Maven. Перейдите в корень проекта и выполните блок из раздела 3:

```powershell
Set-Location -LiteralPath 'D:\Music\policl7'
```

Затем, не закрывая это окно, запустите тесты:

```powershell
.\mvnw.cmd -f microservices/pom.xml test
```

Успех — завершение с `BUILD SUCCESS` и нулевым числом ошибок/проваленных тестов. В наборе есть интеграционный тест общего JDBC-сеанса и тесты контроля доступа к чужим приёмам и медицинским записям. Если в ошибке имя пользователя БД осталось текстом `${MEDICAL_DB_USERNAME}`, переменные не были загружены в это окно: выполните блок из раздела 3 здесь и повторите тесты. Не присылайте пароль или полный текст настроек.

Для безопасной проверки компиляции и сборки корневого монолита, не запуская его тесты:

```powershell
.\mvnw.cmd -DskipTests package
```

Эта команда не доказывает, что тесты монолита прошли. Не запускайте корневой `mvnw test` без проверки профиля: настройки монолита по умолчанию могут автоматически обновлять схему PostgreSQL. Если тесты завершаются ошибкой, сохраните последние строки сообщения без паролей и секретов.

## 5. Запустите приложения

Сначала проверьте порты:

```powershell
@(8080,8081,8082,8083,8084,8761,8888) | ForEach-Object {
  $port = $_
  $listening = Get-NetTCPConnection -LocalPort $port -State Listen -ErrorAction SilentlyContinue
  if ($listening) { "Порт $port занят" } else { "Порт $port свободен" }
}
```

Если порт **свободен**, соответствующее приложение можно запускать по инструкции ниже. Если порт **занят**, это не обязательно ошибка: приложение может быть уже запущено. Не запускайте второй экземпляр и не завершайте процесс наугад. Сначала проверьте сервис:

| Порт | Проверка уже запущенного приложения | Ожидаемый результат |
|---:|---|---|
| 8888 | `(Invoke-RestMethod 'http://localhost:8888/actuator/health').status` | `UP` |
| 8761 | `(Invoke-RestMethod 'http://localhost:8761/actuator/health').status` | `UP` |
| 8080 | `(Invoke-RestMethod 'http://localhost:8080/actuator/health').status` | `UP` |
| 8081 | `(Invoke-RestMethod 'http://localhost:8081/actuator/health').status` | `UP` |
| 8082 | `(Invoke-RestMethod 'http://localhost:8082/actuator/health').status` | `UP` |
| 8083 | `(Invoke-RestMethod 'http://localhost:8083/actuator/health').status` | `UP` |
| 8084 | `(Invoke-WebRequest 'http://localhost:8084/login' -UseBasicParsing).StatusCode` | HTTP `200` |

Если все семь портов заняты и проверки прошли, приложения уже работают: пропустите команды запуска и переходите к разделу 6. На 8084 проверяйте именно `/login`: защищённый `/actuator/health` может перенаправить на HTML-страницу входа, поэтому по нему нельзя считать поле `status`. Если занятый порт не отвечает ожидаемо, сначала выясните, какой процесс его занимает; не запускайте второй сервис на том же порту и не останавливайте неизвестный процесс.

Запускайте только отсутствующие приложения, в указанной последовательности. Для каждого запуска откройте отдельное окно PowerShell и оставьте его открытым. Команды предполагают, что корень проекта — `D:\Music\policl7`; замените путь при необходимости.

### Шаг 1 — Config Server (8888)

Назначение: раздаёт централизованные настройки. Если порт 8888 занят и health-проверка показывает `UP`, Config Server уже работает — не запускайте второй экземпляр. Проверьте, что он отдаёт конфигурацию. Если порт свободен, запустите его в отдельном окне:

```powershell
Set-Location -LiteralPath 'D:\Music\policl7'
.\mvnw.cmd -f microservices\config-server\pom.xml spring-boot:run
```

Дождитесь строки о запуске приложения и проверьте из другого окна:

```powershell
Invoke-RestMethod 'http://localhost:8888/actuator/health' | Select-Object status
Invoke-RestMethod 'http://localhost:8888/identity-service/default' | Select-Object name, profiles
```

Ожидается `UP` и имя `identity-service`. Если настройки не найдены, проверьте запуск команды из корня: Config Server ищет конфигурации в `microservices/config-repo`.

### Шаг 2 — Eureka Server (8761)

Назначение: реестр сервисов. Если порт 8761 занят и health-проверка показывает `UP`, Eureka уже запущен — не запускайте второй экземпляр. Если порт свободен, запустите в новом окне:

```powershell
Set-Location -LiteralPath 'D:\Music\policl7'
.\mvnw.cmd -f microservices\eureka-server\pom.xml spring-boot:run
```

Панель: [http://localhost:8761](http://localhost:8761). Пока бизнес-сервисы не запущены, список может быть пустым. Проверка здоровья:

```powershell
Invoke-RestMethod 'http://localhost:8761/actuator/health' | Select-Object status
```

### Шаг 3 — монолит для веб-страниц (8084)

Он обслуживает сохранённый Thymeleaf-интерфейс. Это тот же исходный проект, но с безопасными для cloud-режима настройками проверки схемы и JDBC-сессий. Если порт 8084 свободен, запустите монолит в отдельном окне:

```powershell
Set-Location -LiteralPath 'D:\Music\policl7'
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=cloud'
```

Не убирайте параметр `cloud`. Если порт 8084 занят, не запускайте ещё один монолит. Проверьте доступность страницы входа:

```powershell
Invoke-WebRequest 'http://localhost:8084/login' -UseBasicParsing | Select-Object StatusCode
```

Ожидается HTTP `200`. Запрос к `/actuator/health` на этом порту может вернуть HTML страницы входа из-за Spring Security, а не JSON health-ответ.

### Шаг 4 — бизнес-сервисы (8081, 8082, 8083)

Для каждого сервиса сначала проверьте его порт. Если порт занят и `/actuator/health` показывает `UP`, сервис уже запущен — пропустите и блок загрузки переменных, и команду запуска. Если порт свободен, откройте отдельное окно PowerShell, перейдите в корень, выполните блок загрузки переменных из раздела 3, а затем команду нужного сервиса.

**Identity Service (8081):**

```powershell
.\mvnw.cmd -f microservices\identity-service\pom.xml spring-boot:run
```

**Appointment Service (8082):**

```powershell
.\mvnw.cmd -f microservices\appointment-service\pom.xml spring-boot:run
```

**Medical Record Service (8083):**

```powershell
.\mvnw.cmd -f microservices\medical-record-service\pom.xml spring-boot:run
```

Каждое приложение должно сообщить об успешном запуске без ошибки порта или подключения к БД. В новом окне проверьте:

```powershell
8081,8082,8083 | ForEach-Object {
  $port = $_
  try { $health = Invoke-RestMethod "http://localhost:$port/actuator/health" -TimeoutSec 5; "$($health.status) :$port" }
  catch { "Нет ответа на порту $port — проверьте окно соответствующего сервиса" }
}
```

### Шаг 5 — API Gateway (8080)

Gateway запускается после Config Server, Eureka и сервисов, чтобы найти назначения маршрутов. Если порт 8080 занят и health-проверка показывает `UP`, Gateway уже запущен — повторно его не запускайте. Если порт свободен, запустите в отдельном окне:

```powershell
Set-Location -LiteralPath 'D:\Music\policl7'
.\mvnw.cmd -f microservices\api-gateway\pom.xml spring-boot:run
```

Проверка здоровья: `http://localhost:8080/actuator/health`.

### Как остановить и перезапустить

Чтобы штатно остановить сервис, выберите его окно и нажмите `Ctrl+C`, дождитесь завершения, затем запускайте снова. Не завершайте Java-процессы через Диспетчер задач, если не уверены, что это процесс именно вашего окна. Переменные БД для микросервисов при новом запуске загрузите заново в их окнах. При изменении конфигурации перезапустите зависимое приложение; обычно порядок перезапуска: Config Server, затем нужный сервис, затем Gateway.

## 6. Проверьте инфраструктуру и маршруты

### 6.1 Общая проверка здоровья

В любом дополнительном окне выполните:

```powershell
$ports = 8888,8761,8080,8081,8082,8083
foreach ($port in $ports) {
  try { $h = Invoke-RestMethod "http://localhost:$port/actuator/health" -TimeoutSec 4; "$($h.status) http://localhost:$port/actuator/health" }
  catch { "ОШИБКА http://localhost:$port/actuator/health" }
}
```

Ожидается `UP` для всех шести адресов. Монолит на 8084 проверьте отдельно:

```powershell
Invoke-WebRequest 'http://localhost:8084/login' -UseBasicParsing | Select-Object StatusCode
```

Ожидается HTTP `200`. Запрос к `http://localhost:8084/actuator/health` может вернуть HTML страницы входа из-за Spring Security, а не JSON с полем `status`; не считайте такую страницу health-ответом. Проверка `/login` подтверждает доступность веб-интерфейса, но не заменяет health-check Actuator. Статус `UP` у остальных приложений тоже не доказывает работу каждого пользовательского сценария.

### 6.2 Config Server

```powershell
$cfg = Invoke-RestMethod 'http://localhost:8888/identity-service/default'
$cfg.name
$cfg.propertySources | ForEach-Object { $_.name }
```

Ожидаемое имя — `identity-service`; среди источников должны отображаться конфигурации из `microservices/config-repo`. Не публикуйте полный ответ: в конфигурации могут присутствовать чувствительные значения/ссылки.

### 6.3 Eureka

Откройте [панель Eureka](http://localhost:8761). Должны зарегистрироваться `API-GATEWAY`, `IDENTITY-SERVICE`, `APPOINTMENT-SERVICE`, `MEDICAL-RECORD-SERVICE` (регистрация Gateway может появиться после его запуска). Проверка через PowerShell:

```powershell
$apps = (Invoke-RestMethod 'http://localhost:8761/eureka/apps' -Headers @{ Accept = 'application/json' }).applications.application
$apps | ForEach-Object { $_.name }
```

### 6.4 Маршруты Gateway

```powershell
$routes = Invoke-RestMethod 'http://localhost:8080/actuator/gateway/routes'
$routes | ForEach-Object { $_.route_id }
```

Ожидаются маршруты `identity-service`, `appointment-service`, `medical-record-service`, `legacy-thymeleaf-application`. Основные пути:

| Через Gateway | Назначение |
|---|---|
| `/api/auth/**`, `/api/users/me`, `/api/admin/users/**` | Регистрация, профиль, администрирование пользователей |
| `/api/appointments/**`, `/api/services/**` | Приёмы и услуги |
| `/api/medical-records/**`, `/api/prescriptions/**` | Медицинские записи и назначения |
| `/`, `/login`, `/registration`, `/appointments` и остальные веб-страницы | Монолит Thymeleaf на 8084 |

Пример проверки маршрута публичных услуг (должен требовать вход, поэтому `401` для гостя может быть ожидаемым):

```powershell
try { Invoke-WebRequest 'http://localhost:8080/api/services' -UseBasicParsing -TimeoutSec 5 | Select-Object StatusCode }
catch { if ($_.Exception.Response) { [int]$_.Exception.Response.StatusCode } else { 'Нет соединения с Gateway' } }
```

`401` означает, что маршрут ответил и потребовал аутентификацию; это не ошибка доступности. После входа выполните проверку через браузер либо с той же cookie-сессией.

### 6.5 Actuator и журналы

Для каждого приложения проверяйте `/actuator/health` на его порту. Gateway дополнительно предоставляет список маршрутов `/actuator/gateway/routes`. В микросервисах через Gateway endpoint Actuator не проксируется автоматически; проверяйте их напрямую по портам 8081–8083. В окнах запуска отображаются журналы. Ищите `Started ...` при успешном старте; при сбое — первую строку `ERROR` и основную причину ниже. Перед отправкой журналов удалите логины, пароли, cookies и медицинские данные.

Если Swagger показывает операции, проверьте их описания. Защищённые операции требуют входа; не отключайте security и не используйте реальные медицинские сведения. Для быстрой проверки JSON:

```powershell
8081,8082,8083 | ForEach-Object {

```

Ожидается HTTP 200 на всех адресах.

## 8. Проверьте пользовательские сценарии

Работайте только с тестовыми данными. Не вводите реальные медицинские сведения. Регистрация приложения создаёт пользователя-пациента; готовые логины/пароли в проекте не предполагаются.

### Регистрация, вход, личная страница и выход

1. Откройте [http://localhost:8080/registration](http://localhost:8080/registration) — запрос проходит через Gateway к веб-приложению.
2. Зарегистрируйте тестового пользователя, указав вымышленные имя, email и пароль. Не используйте свой настоящий пароль.
3. Откройте [http://localhost:8080/login](http://localhost:8080/login) и войдите под созданными данными.
4. После входа должна открыться главная страница. У пациента на ней показываются его записи, если они есть.
5. Нажмите «Выйти». Должна открыться страница входа/сообщение об успешном выходе. Затем защищённый API без входа должен вернуть `401`.

Если регистрация/вход не проходят, проверьте сначала `UP` на 8084 и 8081, затем журналы монолита, Identity и Gateway. Не отключайте CSRF или Spring Security.

### Запись на приём и услуги

1. Войдите как пациент.
2. Откройте [http://localhost:8080/appointments](http://localhost:8080/appointments) и страницу создания записи `/appointments/new`.
3. Выберите услугу и заполните форму тестовыми данными, если каталог содержит доступные варианты.
4. После сохранения новая запись должна отображаться в списке/главной странице пользователя.

Если записей или услуг нет, это может быть пустая существующая база, а не неисправность. Не добавляйте данные напрямую в PostgreSQL без согласованного безопасного способа.

### Ограничение доступа к чужим данным

1. Создайте двух тестовых пациентов через регистрацию.
2. Создайте тестовую запись для первого пользователя штатным интерфейсом, если форма и данные позволяют.
3. Войдите вторым пациентом и проверьте, что список и профиль не показывают запись первого.
4. Не меняйте ID в URL/API с целью читать или удалять чужие данные на рабочей базе. Для демонстрации запрета используйте автоматические тесты владения данными или отдельные временные тестовые записи и только согласованный тестовый стенд.

В проекте есть тесты `AppointmentOwnershipTest` и `MedicalRecordOwnershipTest`, проверяющие защиту операций с чужими объектами. Не создавайте врача/администратора редактированием ролей или БД. Для сценариев DOCTOR и ADMIN используйте только выданную ответственным лицом тестовую учётную запись. Регистрация создаёт PATIENT; автоматического публичного получения привилегированных ролей нет.

### Роли врача и администратора

После получения доверенных тестовых учётных данных войдите через обычную страницу `/login`. Проверьте только разрешённые проектом действия: административная зона — для ADMIN; медицинские страницы записей/назначений защищены и предназначены для привилегированных ролей по правилам проекта. Если таких учётных записей нет, честно укажите преподавателю, что сценарий этой роли не демонстрировался; не меняйте роль через базу.

## 9. Circuit Breaker (безопасная демонстрация)

Gateway имеет Circuit Breaker для Identity, Appointment и Medical Record, тайм-ауты и единый fallback с HTTP 503 и JSON-сообщением о временной недоступности. Не проверяйте это, останавливая неизвестный процесс.

1. Убедитесь, что все сервисы запущены и обычный запрос к выбранному сервису отвечает.
2. Если каждый сервис запущен в отдельном окне вами, остановите только окно одного тестируемого сервиса сочетанием `Ctrl+C`.
3. Повторите через Gateway соответствующий API-путь: `/api/users/me`, `/api/services` или `/api/medical-records` (в зависимости от отключённого сервиса).
4. Ожидается контролируемый ответ `503 Service Unavailable`, а не зависание Gateway.
5. Немедленно перезапустите остановленный сервис и дождитесь его регистрации/`UP`.

Выполняйте такой тест только если приложение не используют другие люди и вы уверены, что остановите именно собственное окно. Не воспроизводите отказ на общей/учебной базе во время чужой работы. Ранее отдельно проверялся fallback Appointment; отказные сценарии двух остальных сервисов проверяйте только в безопасной локальной среде.

## 10. Диагностика типовых проблем

| Симптом | Что проверить |
|---|---|
| `Address already in use` / порт занят | Найдите приложение, занимающее порт: `Get-NetTCPConnection -LocalPort 8080 -State Listen`. Не завершайте неизвестный PID; используйте свободный порт только после проверки конфигурации либо штатно остановите своё старое окно. |
| Сервис не подключается к PostgreSQL | Проверить `Test-NetConnection localhost -Port 5433`, службу PostgreSQL, затем загрузку `MEDICAL_DB_*` в том же окне запуска. Не печатайте значения переменных. |
| `Config Server` не отдаёт файл | Запущен ли порт 8888; команда запуска выполнена из корня `policl7`; файл нужного сервиса есть в `microservices/config-repo`. |
| Сервис не появился в Eureka | Проверить Eureka на 8761, Config Server на 8888, адрес регистрации в конфигурации и журнал самого сервиса. Дайте несколько секунд после старта. |
| Через Gateway `503` | Проверьте, что целевой бизнес-сервис `UP` и зарегистрирован в Eureka. Если он остановлен намеренно, `503` — ожидаемый fallback. |
| Через API `401` | Для защищённых адресов это ожидаемо без входа. Войдите через веб-форму Gateway и повторите; не отключайте защиту. |
| Монолит не запускается или схема не совпадает | Убедитесь, что использован профиль `cloud`, и что подключение идёт к ожидаемой существующей БД. Не меняйте `ddl-auto`, не запускайте миграции/скрипты изменения схемы без проверки и отдельного согласования. |
| Swagger/Actuator не открывается | Проверьте точный порт и `UP`; Swagger открыт по портам 8081–8083, health — `/actuator/health`. |

## 12. Короткий план демонстрации преподавателю (5–10 минут)

6. Показать результаты тестов общего сеанса и проверки владения данными.
7. При безопасной возможности продемонстрировать один Circuit Breaker: временно остановить только свой сервис, увидеть 503, восстановить сервис.
